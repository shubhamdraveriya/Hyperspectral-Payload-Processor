# Moving the project to another computer

The project travels as two zip files, made on 2026-10-15:

| File | Contents | Needed? |
|---|---|---|
| `HPDP_<date>.zip` | the repository with its whole git history (`.git`), the final builds and their reports, the built apps, the real-data results and the latest board-test logs | yes |
| `HPDP_datasets_<date>.zip` | the public hyperspectral datasets, about 4 GB (`data/hsi/`) | only for the real-data experiment; they can also be downloaded again (docs/real_data.md) |

Unzip `HPDP_<date>.zip` anywhere; a path with spaces is fine (the scripts reach the
tools through directory junctions, below). Unzip the datasets zip into the same
folder: it holds `data/hsi/...`.

## What is in the main zip besides the repository

| Path | What |
|---|---|
| `build/m7h/hpdp.xsa`, `build/m7h/reports/` | the final 512-pixel build (bitstream inside the XSA), timing, utilization, CDC and methodology reports, the VER-09 check |
| `build/m7i_1024b/hpdp.xsa`, `build/m7i_1024b/reports/` | the `NX_MAX` 1024 build (SYS-04) |
| `vitis/hpdp_run/build/hpdp_run.elf` | the A53 application, built against m7h (works with both builds); `run_m5.py`'s default `--elf` |
| `build/vitis_sdput/sd_put/build/sd_put.elf` | the SD card writer (`sw/host/sd_put.py --elf ...`) |
| `build/real_data_results.*`, `build/real_data_experiment.log` | the real-data experiment's raw results (docs/real_data.md has the tables) |
| `build/logs/` | console logs of the post-M7 board tests (docs/post_m7_board_tests.md) |

Not included, because they are regenerated by the scripts: the Vivado project folders
(`build/*/vivado`), the simulation folder (`build/sim`), the Vitis workspaces (the
whole of `vitis/` except the ELF), the board-run work folders (`build/runs/`), the
Python virtual environment (`.venv/`) and the exported test scenes (`data/hsi/export`,
`data/sdcard`, rebuilt with `model/hpdp_datasets.py export` and
`model/hpdp_tool.py gen`, docs/post_m7_board_tests.md).

## Tools

- **Vivado and Vitis 2025.2** with Zynq UltraScale+ support (the XCZU7EV); licence as
  on this computer (O-4). Here they are in `C:\AMDDesignTools\2025.2`. Elsewhere,
  pass `--xsdb <path to xsdb.bat>` to the host scripts (`sw/host/run_m4.py` keeps the
  default path in `XSDB`), and put Vivado's and Vitis's `bin` folders on `PATH`.
- **Python 3.10 or later** (3.14 here):

```
python -m pip install -r requirements.txt
python -m venv .venv
.venv\Scripts\python -m pip install -r sw\ground\requirements.txt
```

The first line serves the models, tests and register generator; the venv serves the
ground station's display (numpy, matplotlib).

## Directory junctions

Vivado's and Vitis's tools fail on paths with spaces and on very long paths
(docs/m0_bringup.md, issue 3), so the scripts reach folders of the repository through
junctions in the home folder, created on first use (no administrator rights):

| Junction | Points to | Made by |
|---|---|---|
| `~/hpdp_vitis_ws` | `vitis/` | `sw/baremetal/build.py` |
| `~/hpdp_runs` | `build/runs/` | `sw/host/run_m4.py`, `run_m5.py` |
| `~/hpdp_sdput_ws` | `build/vitis_sdput/` | `sw/baremetal/build_sd_put.py` |
| `~/hpdp_build` | `build/` | by hand, only for a second app workspace (`HPDP_VITIS_WS=~/hpdp_build/vitis_next`) |

If one of them exists on the new computer and points elsewhere, the scripts stop with
a message; remove it (it is only a link) and run again.

## Checking the copy

```
python -m pytest model                                   # 150 tests, seconds
python -m pytest sw/ground                               # ground station
vivado -mode batch -source tb/run_sim.tcl                # RTL regression, 87 tests, about 10 minutes
git log --oneline | head                                 # the history came along
```

## Rebuilding

```
vivado -mode batch -source vivado/build.tcl              # bitstream and XSA (HPDP_BUILD_DIR; HPDP_NX_MAX=1024)
vitis -s sw/baremetal/build.py build/m7h/hpdp.xsa        # the app, workspace vitis/
python -I model/hpdp_datasets.py experiment -j 5         # real-data results (needs the datasets)
```

## The board

docs/m0_bringup.md (DDR4 SODIMM settings, JTAG boot override, the UART port), then the
runbooks: docs/m7_board_runbook.md and docs/post_m7_board_tests.md, which lists the
connections each test needs (the fiber looping SFP0 and SFP1, an SD card, Ethernet).
Every run is JTAG-only; nothing writes the flash.
